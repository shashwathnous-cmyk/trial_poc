## Work Items

- **[56696]** Procurement Portal Access and Navigation
- **[56726]** As a Procurement Portal User, I want to view procurement lifecycle status and history so that I can track the progress of my procurement work (5 pts)
  Acceptance:
1. System displays the current lifecycle status on the procurement request detail page for an authorized user
2. System shows procurement request status history in chronological order with timestamps and action context for each recorded change
3. System displays a clear empty state when no history exists beyond initial request creation instead of leaving the history area blank
4. System preserves access to the same procurement request detail page after browser refresh or direct URL entry when the user remains authorized
5. System blocks unauthorized access to procurement request detail and history endpoints and does not expose request information for restricted identifiers
- **[56717]** As a Procurement Portal User, I want to create and save a procurement lifecycle request so that my procurement work can begin within the portal (8 pts)
  Acceptance:
1. System provides a procurement request form with visible labels, logically grouped fields, and inline validation in line with Design/guidelines.txt
2. System creates a procurement request successfully when the user submits all required baseline information and returns a unique request identifier with an initial lifecycle status
3. System prevents request creation when required baseline fields are missing and displays field-level messages that identify what must be completed
4. System allows the user to save request progress as a draft and resume the same procurement request later without losing previously saved information
5. System prevents duplicate request records when the user clicks save multiple times or retries after a transient client interruption
6. System records request creation and draft-save events in the audit trail with actor, timestamp, request identifier, and action outcome
- **[56742]** As a Procurement Compliance Analyst, I want an audit trail of procurement portal activity so that procurement lifecycle actions remain traceable and reviewable (5 pts)
  Acceptance:
1. System creates audit entries for tracked procurement portal actions including request creation, draft save, status change, and authentication events
2. System stores each audit entry with mandatory metadata including actor identifier, timestamp, action type, target item identifier, and outcome
3. System allows authorized reviewers to retrieve procurement audit history in chronological order for a selected procurement request or event filter
4. System exports audit results in a reviewable format that matches the selected scope and logs the export request as a separate audit event
5. System prevents unauthorized users from viewing, modifying, or deleting procurement audit records
- **[56735]** As a Procurement Process Owner, I want procurement lifecycle states and transitions to be configurable so that the portal can support the approved process scope without hardcoded assumptions (8 pts)
  Acceptance:
1. System stores procurement lifecycle states and allowed transitions in configuration that can be read by the portal and workflow services
2. System validates every procurement status change against the configured allowed transitions before updating the request record
3. System blocks undefined or invalid transitions and returns a clear message indicating that the requested lifecycle move is not allowed
4. System records successful and rejected transition attempts in the audit trail with request identifier, previous state, requested state, actor, timestamp, and outcome
5. System restricts workflow configuration changes to authorized roles and blocks non-authorized access to configuration endpoints
- **[56699]** As a Procurement Portal User, I want to sign in to the procurement portal so that I can securely access procurement lifecycle functions (5 pts)
  Acceptance:
1. System displays a sign-in page with visible field labels, keyboard-accessible controls, and a single primary action button in line with Design/guidelines.txt
2. System authenticates valid procurement portal credentials and redirects the user to the procurement portal landing page with an active authenticated session
3. System rejects invalid or missing credentials, prevents access to protected procurement portal routes, and displays inline error messages that explain what must be corrected
4. System preserves authenticated access across browser refresh and standard portal navigation until the session expires or the user signs out
5. System redirects users with expired or invalid sessions to the sign-in page and displays a clear message that the session is no longer valid
- **[56708]** As a Procurement Portal User, I want to navigate the procurement portal through clear menus and breadcrumbs so that I can reach procurement lifecycle areas efficiently (5 pts)
  Acceptance:
1. System displays persistent primary navigation on procurement portal pages and highlights the active section using visual treatment consistent with Design/guidelines.txt
2. System shows breadcrumbs on multi-level procurement pages so users can identify the current location and navigate back through the page hierarchy
3. System supports direct URL entry, browser refresh, and browser back-forward actions without losing the authorized route context or breaking the page
4. System hides unauthorized procurement routes from navigation menus and blocks direct access attempts to those routes on the server side
5. System keeps navigation visible during loading, empty, and recoverable error states so users can continue portal movement without confusion
